## 三、重新生成前端数据

```bash
cd valorant-intel

# 1. 抓增量（按需）
python3 pipeline/crawl_recent.py results     # 新赛果
python3 pipeline/crawl_recent.py upcoming    # 待赛
python3 pipeline/crawl_news.py 5             # 新闻 5 页
python3 pipeline/crawl_rosters.py            # 阵容（只抓 ELO 前 90 + 中国重点队）

# 2. 新比赛补逐图数据（可选，慢）
python3 pipeline/crawl_details.py            # 读 data/detail_queue.jsonl

# 3. 重跑模型（新增比赛后）
python3 pipeline/model.py --final

# 4. 打包成 web/assets/data/*.js
python3 pipeline/build_data.py
```

`build_data.py` 会重写 `web/assets/data/` 下的：

| 文件 | 内容 | 体积约 |
|---|---|---|
| `meta.js` | 统计、模型、译名、赛事索引、详情索引 | 24 KB |
| `core.js` | 3,820 选手 + 5,298 战队 | 885 KB |
| `roster.js` | 244 支队伍的阵容（38 支现役） | 45 KB |
| `matches-YYYY.js` | 按年切分比赛 | 320–930 KB/年 |
| `records.js` | 选手生涯记录（懒加载） | 2.5 MB |
| `details.js` | 逐图/选手数据（懒加载） | 1.6 MB |
| `intel.js` | 待赛 + 新闻 | 61 KB |

## 四、更新新闻中文

1. 跑 `crawl_news.py` 后，新条目在 `data/news.json` 里只有英文。
2. 在 `data/news_zh.json` 按 `新闻ID` 增加：
   ```json
   "784188": {"title": "中文标题", "summary": "一句中文摘要"}
   ```
3. 重跑 `build_data.py`。
4. App 内在线刷新抓到的新条目不会自动翻译，会先显示英文；下次重建时补上中文即可。

## 七、口径与坑

1. **比赛日期**：vlr 列表页格式是 `Fri, May 29, 2026`，不是 `May 29, 2026`；两种都要兼容。抓取时曾因只解析后者导致“0 场新赛果”。
2. **BO 制式**：列表页不直接给 Bo；用 `max(比分)` 反推（1=Bo1，2=Bo3，3=Bo5）。
3. **新赛果逐图数据缺失**：vlr 新页面（`.ovw-*`）与旧页面（`.vm-stats-*`）结构不同；已复用旧解析器，Rating/KAST/ADR/HS% 在部分场次本身为空，App 显示“—”。
4. **阵容解析**：战队页同时含 players / staff 两段，必须取 `players` 标签后的第一段，否则会把教练算进阵容。
5. **选手同名**：按小写 ID 去重，保留 VCT 现役优先、生涯场次更多的一条；记录归属还会用 vlrId 校验，避免把 A 的生涯贴到同名的 B 身上。
6. **时区**：待赛的 `utc` 是 UTC 时间，App 展示时转本地时区。
7. **数据快照日期**：`meta.generated` 是构建时间，不是数据截止时间；数据截止看 `meta.range[-1]`。

## 九、地图与跑图（3.0）

### 数据来源
- 点位与地图元信息：`valorant-api.com/v1/maps`（用户从 Safari 取得存为 `data/maps/valorant-api-maps.json`）。
- 俯视图：`media.valorant-api.com/maps/<uuid>/displayicon.png`；莲华古城等下载失败时改用 `spikeatlas.com/minimaps/<uuid>.png`。

### 标定（pipeline/calibrate_maps.py）
**官方公式的轴是对调的**（这是关键更正，素材包实测确认）：
```
u = y * xMultiplier + xScalarToAdd      （u 由世界 y 决定）
v = x * yMultiplier + yScalarToAdd      （v 由世界 x 决定）
```
按字面义（u=x·xm+…）写，点位几乎全溢出画布。逐图实测（点位落在地面的比例）：Ascent 9%→77%、Bind 0%→92%、Fracture 0%→82%。

优先用官方公式；个别图（Split、Breeze、Sunset、Pearl、Haven）官方公式不佳时退回几何拟合：

```
px = (x - x0)/s + dx      py = (y0 - y)/s + dy
未知量：每像素世界长度 s、画布原点 (x0,y0)、像素偏移 (dx,dy)
目标：官方点位落在「地面像素」上的比例最高
做法：质心对齐 → s ∈ {11,11.5,…,17} 粗搜(±120px, 8px 步) → 精搜(±6px, 1px 步)
门槛：命中率 ≥ 70% 才使用点位；未达标的图（源工重镇 62.5%、裂变峡谷 62.5%）只给走图不给点位
```

### 像素语义（踩过的坑）
俯视图并非「灰=墙、白=空地」。实测灰度：
- 白 **255** = 地图外空地
- 浅灰 **≈118** = **地面（可走）**
- 灰 **≈132–145** = 墙/标记线
- 橄榄色 = 站点高亮（也是可走）

第一版把「亮于 240」当实心，后来又把「暗于 240」当实心，两次都错；最终规则是：**可走 = 118 附近 ±10 或橄榄色**。

### 网格
- 世界坐标 → 网格：`CELL_WORLD = 120`（接近角色可站立单位）。
- 每格取中心 3×3 采样，过半是地面才算可走。
- 只保留最大连通块（装饰线会把路切碎），网格外一律不可走。

### 复现
```bash
python3 pipeline/calibrate_maps.py      # 写 data/maps/maps.json（未达标会非零退出）
# 再导出给前端（calibrate 只写 json）：
python3 -c "import json;d=json.load(open('data/maps/maps.json'));open('web/assets/data/maps.js','w').write('window.VD_MAPS='+json.dumps(d,ensure_ascii=False,separators=(',',':'))+';\n')"
```

### 原生 App 的图片加载
WKWebView 里 `file://` 页面给 canvas 画另一张图会被判定跨域，`getImageData` 抛 SecurityError。所以 App 内置了同源代理：

```
http://127.0.0.1:8796/proxy?u=<urlencoded https 地址>
```

`web/assets/js/maplab.js` 在原生环境（注入 `window.__NATIVE_HOST__`）下自动走代理，网页版直接用相对路径。
